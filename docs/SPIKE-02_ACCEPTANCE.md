# SPIKE-02 Bounded Conversion Coverage

SPIKE-02 characterizes the pinned `sas2databricks==0.4.0` deterministic wrapper against three
byte-pinned, attributed SAS programs. The governed corpus intentionally exercises a successful
PROC SQL conversion, a review-required BY-group formatting case, and a zero-step multi-artifact
case. It is a bounded coverage experiment, not an estate coverage percentage.

## Evidence contract

`make spike02-confidence` replays the checked-in corpus descriptor, source and provenance bytes,
then consumes the existing CV-04 package verifier for every subject. The immutable aggregate binds
client/deployment/environment/run/attempt, corpus revision and digest, provider packages and
durations. Replay re-verifies current source, provenance, qualified provider/runtime, generated
artifacts and package manifests before reconstructing the aggregate result.

Classifications have a narrow meaning:

- `supported`: independent behavioral evidence validates the deterministic output (this bounded
  experiment produces no such claim);
- `partial`: the wrapper emitted reproducible generated bytes but has only static syntax evidence,
  or it retained review/escalation evidence;
- `unsupported`: the wrapper reported no meaningful conversion step;
- `unresolved`: provider execution or evidence verification blocked.

Behavioral validation and SAS parity stay `not_executed` / `not_evaluated` for every subject. Static
syntax never substitutes for those claims. A generated static-only result routes to `VAL-01`, a
review-required result to `AIREP-01`, and a deterministic provider gap to `CV-04`. No direct model
provider, SAS, Humana, Databricks or Unity Catalog access occurs.

Run:

```bash
make spike02-confidence
```

The durable local result is written below `out/spike02-coverage/`. Generated output, test counts and
this bounded public/SMF corpus cannot establish SAS semantic parity, customer readiness, production
coverage, migration completion, or the ten-week 1,000-script result.
