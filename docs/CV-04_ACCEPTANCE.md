# CV-04 deterministic conversion package acceptance

CV-04 wraps the approved `sas2databricks` 0.4.0 provider at evaluated revision
`392d3a34c1390f6335fb47e165a4f4f3ac03111c`. It does not implement another SAS
converter. The wrapper executes the byte-qualified code twice over the same admitted immutable source
bytes, requires identical generated bytes and provider metadata, and packages only deterministic
output that contains no unresolved provider review or escalation evidence.

The subprocess receives a credential-free environment. Direct model endpoints, API keys, proxy
settings and caller-selected model options are not forwarded. The fixed upstream threshold is
recorded as evidence; a reported review or LLM escalation becomes an actionable
`UPSTREAM_REVIEW_REQUIRED` exception. AIGW-01/AIREP-01 own any later gateway-assisted repair.
Deterministic success never depends on that repair path.

## Package and evidence contract

Each attempt is isolated under
`runs/<run>/workloads/<workload>/attempts/<attempt>/conversion-packages/<artifact>/`.
The immutable manifest binds:

- client, deployment, environment, workload, source-artifact, run and attempt identities;
- admitted source digest, byte and line counts plus versioned provenance-evidence digest, origin,
  revision and license disposition;
- exact target, entrypoint or non-executable review candidate, and generated digest;
- provider version/evaluated revision, exact normalized RECORD member set, code-manifest digest,
  SMF runner digest and exact MIT license bytes/disposition (the upstream wheel SHA remains a
  planning reference, not a runtime verification claim);
- the admitted Python executable plus privately staged, exact `sqlglot` and `PyYAML` import closure,
  executed with `-I -S`, and the no-runtime-download rule;
- two-run reproducibility measurements, provider summary, exceptions and derived claims.

`packaged` means only that deterministic conversion produced reproducible syntactically valid target
source without unresolved upstream review flags. It does not mean the code executed, reconciled,
passed parity, is production-ready, or completed a migration. `review_required`, `unsupported` and
`blocked` results retain an immutable exception report and cannot be treated as package-ready.
